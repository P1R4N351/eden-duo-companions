# The Legend of Zelda: Tears of the Kingdom — dual-screen companion

Title ID `0100F2C0115B6000`, game version **1.4.3** only (main module ID
`277178B7DBA1B6D4949A84778D4ABC58B31B34F5`). Read-only. Status: **0.1.0, tested in the desktop
host harness only; not yet run on a device.**

## Pages

- **Main page** — laid out like Breath of the Wild's Ready page, the same design as the TotK
  Native Android app's companion main page:
  - a round minimap from the game's own map tiles, north up, Link's arrow in the middle, on the
    layer he is on (Surface, Sky, Depths); a tap opens the Map page;
  - dials round it: Poes, stamina wheels (+ extra), the nearest-shrine slot (a Lightroot in the
    Depths; no distance yet), battery cells (+ extra);
  - corner cards: shield, bow, ability, weapon, each with its icon, name and durability
    (*Breaking!* under 5); the arrows and their count under the bow; the weapon's fused material
    and its durability above the weapon;
  - left pager: **Hearts** (quarters, gloom damage, extra hearts; red when low) / **Sages**
    (with you, cooldown, away); rupees under it;
  - right pager under the layer plate: **Armor** (the three worn pieces) / **Meal** (level, time
    left); a tap or a vertical swipe turns either pager;
  - Link's coordinates; a command bar: Inventory, Map, `- Map` and `+ Menu` (these two press the
    game's own buttons);
  - during a cutscene the page dims; with the pause menu open it says *Purah Pad open on the main
    screen* and only the command bar stays live. The title screen, loading, and another game
    version each get a page of their own.
- **Inventory** — the eight categories (weapons, bows and arrows, shields, armor, materials, food,
  Zonai devices, key items) as icon grids with counts, durability and fused materials; a tap shows
  the item's in-game name, description and facts.
- **Map** — the whole MainField map, pan and zoom (finer tiles when zoomed in), Surface / Sky /
  Depths or *Follow Link*, *Recenter*.

## How it works

- **Game state**: `native/modules/0100F2C0115B6000.cpp` runs TotK Native's companion reader
  (`native/modules/totk_reader/`, MIT, unchanged) over Eden Duo's `read_memory`: the GameData flag
  tables (`gmd::GameDataMgr`), the pouch, the scene's player actor and the pause-menu / event
  state. Before trusting any offset it checks a SHA-256 of eight instructions of `main` that use
  them, so any other build is refused (*unsupported*), and a sample taken while the game tears
  its state down is retaken rather than shown half-changed. Nothing is written and no game code
  is called.
- **No item actions.** TotK Native equips, eats and takes out items by calling the game's own
  pouch functions; Eden Duo offers no guest calls on Android, so this package is read-only. The
  `- Map` / `+ Menu` buttons only press the game's buttons.
- **Art and text** are decoded at runtime from the player's own romfs, as `module:totk:` images:
  item icons (`UI/Tex/Icon/<actor>.bntx.zs`), layout textures from
  `UI/LayoutArchive/Common.Product.140.Nin_NX_NVN.blarc.zs` (`timg/__Combined.bntx`), the map
  tiles (`UI/Map/MainField/`), item names and descriptions (`Mals/USen.Product.*.sarc.zs`,
  `ActorMsg/PouchContent.msbt`) and the game's Rodin font (`Font/Font.Nin_NX_NVN.bfarc.zs`,
  rasterised with the Super Mario Bros. Wonder module's font code). Every TotK `.zs` file is a
  zstd frame compressed with a dictionary from `Pack/ZsDic.pack.zs`; the module loads those
  dictionaries first (`totk_romfs.cpp`). The flat shapes (discs, the minimap's round mask) are
  drawn by the module (`gen/` keys).

## Files

| File | What it is |
|---|---|
| `dualscreen/manifest.json` | The pages. Generated by `tools/totk/gen_manifest.py` |
| `dualscreen/map_tiles.txt` | Which variant of each map tile to draw (file names only, no game data). Generated by `tools/totk/gen_map_tiles.py` from a romfs file list |
| `dualscreen/totk_font.txt` | The font spec the module's `decode_font` reads: `<scft font>:<cap height px>` |

The package ships **no game assets**: no art, text, audio, fonts or level data.

## Build

```sh
python3 tools/totk/gen_manifest.py
cmake -S native/modules -B build-native-android -G Ninja -DEDEN_SOURCE_ROOT=/abs/eden-duo \
  -DCMAKE_TOOLCHAIN_FILE=$ANDROID_NDK/build/cmake/android.toolchain.cmake -DANDROID_ABI=arm64-v8a \
  -DANDROID_PLATFORM=android-24 -DANDROID_STL=c++_static -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build build-native-android --target dsmod-totk
llvm-strip --strip-all -o totk-android.so build-native-android/0100F2C0115B6000.so
python3 tools/build_dualscreen_package.py --package packages/TearsOfTheKingdom --output dist \
  --version 0.1.0 --min-runtime 22 --module android-arm64-v8a=totk-android.so \
  --build-id 277178B7DBA1B6D4949A84778D4ABC58B31B34F5000000000000000000000000
```

## Tested

Only on a desktop: Eden Duo's runtime (at `9ebc508`) built with this module linked in, against
the real 1.4.3 `main` image and a laid-out fake game state (hearts, gear, pouch, sages,
position), reading the owner's own romfs files. Scenes checked: in game (Surface, Sky, Depths),
pause menu, cutscene, title screen, another game version; Inventory with a selected item; the Map
page. Both the Linux x86-64 and the Android arm64 module build without warnings.

## Not yet

- A device run in Eden Duo (AYN Thor / Retroid Pocket Duo).
- The distance to the nearest shrine / Lightroot (needs the location markers from
  `Banc/*/LocationArea`), map pins and stamps, current stamina (only the capacity is read),
  the time of day, an area name.
- Languages other than English (US) for item names and descriptions.
- Item actions (need guest calls).
